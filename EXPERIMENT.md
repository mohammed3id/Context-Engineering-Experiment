# Experiment: Evaluating the Impact of AGENTS.md

## 1. Experiment Overview

This experiment explores the impact of Context Engineering on AI-generated code.

The experiment uses a Node.js and Express API endpoint for an educational Cybersecurity Output Analyzer as a practical development task.

The objective is to compare the results generated by an AI assistant in two different situations:

- **Run A:** The task is provided without project-specific instructions.
- **Run B:** The same task is provided after supplying an `AGENTS.md` file containing project context, security restrictions, and coding guidelines.

The generated implementations are evaluated using predefined security criteria.

## 2. Task Description

The development task is to create a POST API endpoint that receives text containing output from an authorized penetration testing lab exercise and returns a structured educational explanation.

The endpoint should use Node.js and Express.

## 3. Evaluation Criteria

Three checks were defined before conducting the experiment:

- **C1 – Server-side Input Validation:** Does the endpoint validate user input on the server?
- **C2 – Safe Output Handling:** Does the endpoint treat submitted output as data without executing commands?
- **C3 – Sensitive Data Protection:** Does the endpoint avoid exposing sensitive information in responses and logs?

## 4. Experiment Prompt

The following prompt was used in both runs to ensure a fair comparison:

"Create a POST API endpoint for an educational Cybersecurity Output Analyzer using Node.js and Express.

The endpoint should accept text containing penetration testing output from a user's authorized lab exercise and return a structured explanation.

Provide the implementation code and briefly explain how it works."

## 5. Run A: Without AGENTS.md

### 5.1 Generated Implementation

The AI assistant generated a Node.js and Express endpoint using the `/api/v1/analyze` route.

The implementation included:

- JSON request body parsing using Express middleware.
- Server-side validation to check that `outputText` exists, is a non-empty string, and has the correct data type.
- A basic analysis function using keyword matching to identify possible security findings.
- A structured JSON response containing findings, risk levels, descriptions, and remediation suggestions.
- Error handling that returns a generic error message to the client.

### 5.2 Evaluation

| Check | Result | Observation |
|---|---|---|
| C1: Server-side input validation | Pass | Validates the existence, type, and non-empty value of outputText. |
| C2: Safe output handling | Pass | Analyzes submitted text without executing commands. |
| C3: Sensitive data protection | Partial | Returns a generic error message but logs the complete error object. |

### 5.3 Run A Observations

The generated implementation included basic input validation and safe text processing.

However, it did not define a request body size limit or a maximum input length. It also logged the complete error object, which could potentially expose sensitive information in server logs.

## 6. Run B: With AGENTS.md

### 6.1 Generated Implementation

The AI assistant received the AGENTS.md instructions before receiving the same development task.

The generated implementation included:

- JSON request body parsing with a 10 KB size limit.
- Server-side validation to ensure that the submitted output is a non-empty string.
- A maximum input length of 5,000 characters.
- An analysis function that processes only the text explicitly provided by the user.
- Structured JSON responses containing educational explanations and remediation suggestions.
- Generic error messages returned to the client.

### 6.2 Evaluation

| Check | Result | Observation |
|---|---|---|
| C1: Server-side input validation | Pass | Validates input type, empty values, and maximum input length. |
| C2: Safe output handling | Pass | Processes submitted text without executing commands or performing live scans. |
| C3: Sensitive data protection | Partial | Returns a generic error message but logs error.message, which could contain sensitive information. |

### 6.3 Run B Observations

Compared with Run A, the generated implementation introduced additional input restrictions, including a JSON body size limit and a maximum text length.

It also followed the project-specific instruction to analyze only user-provided output and avoid executing commands.

However, the error logging still requires improvement to prevent potentially sensitive information from appearing in server logs.

The analysis function also returned simulated results rather than performing actual analysis or calling an LLM API.

## 7. Comparison Between Run A and Run B

| Evaluation Criteria | Run A: Without AGENTS.md | Run B: With AGENTS.md |
|---|---|---|
| C1: Server-side input validation | Pass | Pass |
| C2: Safe output handling | Pass | Pass |
| C3: Sensitive data protection | Partial | Partial |
| Request body size limit | Not implemented | 10 KB |
| Maximum input length | Not implemented | 5,000 characters |

### Comparison Analysis

Both implementations demonstrated basic security practices, including server-side input validation and safe handling of submitted output.

However, Run B introduced additional input restrictions, such as a request body size limit and a maximum input length.

This suggests that providing project-specific instructions through AGENTS.md can guide an AI assistant toward generating code that better reflects the project's requirements.

Nevertheless, both implementations still require improvements in error logging to ensure that sensitive information is not exposed.

## 8. Conclusion

The experiment demonstrated that Context Engineering can influence AI-generated code by providing structured project-specific instructions.

Run B included additional input restrictions compared with Run A, showing that AGENTS.md helped guide the generated implementation toward the defined security requirements.

However, the experiment also showed that AI-generated code is not automatically secure. Both implementations required further improvements in error handling and logging.

Overall, clear context and instructions can improve the relevance and consistency of AI-generated solutions, but human review and testing remain essential.
